Diff and merge
beyond text.

Format-aware diff, three-way merge, and patch for files that line-based tools handle badly.

Images, archives, structured data, PDFs, databases, and 3-D meshes — parsed into their semantic units and merged unit by unit, then written back as a valid file. One C++ tool, splinter, that runs standalone and as a Git textconv, diff driver, and merge driver.

Get a copy

There are no binary releases yet, so you build from source. Clone the repository and follow BUILDING.md — it's C++20 with CMake and vcpkg.

# over HTTPS
git clone https://github.com/AlphaPixel/SemanticSplinter.git

# or with the GitHub CLI
gh repo clone AlphaPixel/SemanticSplinter

The tool lands at build/<preset>/src/cli/Release/splinter (splinter.exe on Windows). splinter --version prints the version for bug reports.

Why it exists

A one-pixel edit to a PNG changes most of its compressed bytes. Git shows "Binary files differ" and cannot merge two artists' edits to different parts of the same image. Splinter parses each format into its semantic units — pixels, chunks, archive members, XML elements, JSON keys, table rows, PDF objects — diffs and merges those, and writes a valid file back.

  • Untouched data is copied byte for byte. Only changed units are re-encoded, so Git deltas stay small.
  • Plumbing is handled for you. Sizes, offsets, CRCs, and checksums are recomputed; compressed streams are compared by content, so recompression noise is never a change.
  • No silent best effort. When two sides edit the same unit it reports a conflict with a deterministic ID — it never averages or guesses.
  • Familiar interface. splinter a.png b.png behaves like diff, -m like diff3 -m, -P like patch; exit codes follow the tool being emulated.

What it looks like

splinter old.png new.png                  # changed regions, metrics, metadata
splinter -u old.png new.png               # unified diff over canonical dump lines
splinter --json=report.json a.png b.png   # machine-readable report
splinter -m mine.png base.png theirs.png  # three-way merge, as diff3 -m
splinter -m mine.zip base.zip theirs.zip  # members merged by path, each by its format
splinter -m mine.db  base.db  theirs.db   # SQLite: rows by key, cells merged
splinter --binary a.png b.png > logo.patch  # an applicable semantic patch
splinter -P < logo.patch                  # apply it, as patch
splinter git-setup                        # wire up as Git diff + merge driver
