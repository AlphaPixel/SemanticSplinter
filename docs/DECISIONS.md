# Open Decisions

Every choice made while drafting the specification is listed here. Each started with a **provisional** answer; every
v1 decision is now decided (see below). To settle or amend one, change **Status**, record who decided it and when,
and fix any document that disagrees.

Status values: `Provisional`, meaning drafted and assumed but not reviewed; `Decided` (`amended` when the owner changed
the answer, and the answer column then shows the decided text); `Deferred`, meaning out of v1 scope; `Re-examine`, meaning
the owner asked for more explanation first; and `Superseded`.

Three review rounds on 2026-10-08 (decision register artifact) decided or deferred every project-level decision and every
format question of the v1 formats. Unanswered format questions belong to formats outside the v1 plan (D-44) and stay provisional.

Trusted: 0 equal, 1 different, 2 trouble. | D-18 | Real-world fixtures | Separate LFS-backed corpus repository referenced by CI. Generated fixtures in-tree | Everything in-tree | Keeps the main repository small and avoids license questions about sample files | Decided 2026-10-08 |

The dependency rule keeps the default static binary free of copyleft obligations, so anyone can embed the library | Decided 2026-10-08 (amended) |
| D-20 | Lossless round-trip requirement | Semantic losslessness is mandatory. Byte-exactness is required for untouched units wherever the format allows. Re-encoded units must be semantically equal, and the difference is reported | Byte-exact everything, or semantic only | Byte-exact re-emission of modified containers is often impossible (compression), but silent semantic loss is never acceptable | Decided 2026-10-08 |
| D-21 | Output on conflict | Follow Git: always write a complete file to `%A` and exit 1. All other formats default to `ours`, as Git's binary driver does | Write nothing; write `mark` by default | Git requires `%A` to hold a file. Ours matches Git's conflict-stage intuition. `mark` is a per-repo opt-in | Decided 2026-10-08 (amended) |
| D-22 | Report formats | JSON, Markdown (`--md`), plus GNU-style text renderers. No HTML in v1 | HTML report | A GUI or HTML renderer can consume the JSON later | Decided 2026-10-08 (amended) |
| D-23 | Distribution artifact on Windows | Single static `splinter.exe` (`x64-windows-static`), plus copies for the aliases | Dynamic DLLs; installer | Simplest to drop on PATH and to use from Git for Windows | Decided 2026-10-08 |
| D-24 | Unicode and paths on Windows | `wmain` with conversion to UTF-8 at the edge, `std::filesystem::path` internally, and a UTF-8 active code page manifest | Narrow `main` only | Paths with non-ASCII characters are common in asset repositories | Decided 2026-10-08 |
| D-25 | Subcommand words vs files named `diff`/`merge` | A subcommand word in the first position always wins. Use `./diff` or `--` for such files | Prefer an existing file | Deterministic behaviour beats guessing from the filesystem | Decided 2026-10-08 |
| D-26 | XML parser | expat (MIT) tokenizer plus an own tree with byte spans and a splice writer (xml.md) | pugixml DOM | Byte-exact re-emission of untouched subtrees needs start *and* end offsets, which pugixml lacks. That matters for text-visible XML such as SVG in Git | Decided 2026-10-08 |
| D-27 | ZIP implementation | Own reader and writer over zlib and zstd (containers.md §9). minizip-ng was the MVP plan; the Phase 6 spike rejected it | minizip-ng in raw mode; libzip | **Spike (2026-10-10, minizip-ng 4.1.0 source):** `mz_zip_writer_copy_from_reader` re-serializes every local header from the central record (`mz_zip_entry_write_header`), so local-only extras are lost; it regenerates and moves ZIP64, NTFS, and Unix1 extras ahead of the others, rewrites `\` to `/` and truncates names and comments at NUL, chooses its own data descriptors, and models neither prefix data, the APK Signing Block, nor zipalign padding. Byte-exact raw span copy is impossible through its API, and §8.1 limits would need a custom stream. The own ZIP and TAR modules plus their shared member layer are about 2.8k lines | Decided 2026-10-08 (amended 2026-10-10) |
| D-28 | Shared code between formats | Internal helper modules: `semantic-splinter-raster`, `geomcore`, `src/core/{diff,align,text}`, `common/splice` (SPEC §2.3) | Format modules depending on each other | Avoids format modules depending on unrelated formats only to reuse code | Decided 2026-10-08 |
| D-29 | Diff algorithm source | Own clean-room Myers + histogram + patience + diff3 (~1.7k LOC), written from published descriptions, matching or exceeding Git's xdiff output quality. No xdiff source is read or adapted. A later optional feature may build and link libgit2/xdiff | Link libgit2/xdiff; dtl | License (D-19) and feature fit. GNU diffutils (GPLv3) is a black-box test oracle only | Decided 2026-10-08 (amended) |
| D-31 | PDF rendering | No PDF rasterization in v1. Structure, text, metadata, annotations, and forms come from qpdf. PDFium as an optional `pdf-render` feature is reconsidered after v1 | MuPDF (AGPL), Poppler (GPL) — both rejected | Only permissive option. Text and structure diff (qpdf, Apache-2.0) works without rendering | Decided 2026-10-08 (amended) |
| D-32 | GridMerge shape changes | One-sided reshape wins only if the other side did not edit the grid. Otherwise `shape-mismatch` (SPEC §5.1, adopted from Q-PNG-3) | Reshaping side always wins | The original draft rule silently dropped edits, which violates "no silent best-effort" | Decided 2026-10-08 |
| D-34 | Envelope model | Seven byte classes (content, framing, integrity, authenticity, encoding, derived, volatile), plus an EnvelopeMap per document, churn attribution, and a shared fix-up Emitter (SPEC §12). Section 7.1 of every format document inventories the fields, and ENVELOPES.md catalogs them | Per-format ad-hoc handling | Sizes, checksums, and compressed streams appear in most binary formats. | D-35 | Signature handling | `--signatures=auto` chooses per format the option that leaves a loadable file (strip JAR/APK/NuGet signatures, keep PDF signatures through incremental updates). `resign` only with a user-supplied **private** key or an external signer | Always keep invalid signatures; always strip | A public key verifies but cannot sign. | D-36 | Crypto library | OpenSSL 3 libcrypto (vcpkg `openssl` 3.6.4, Apache-2.0) as the `crypto` feature, on in release builds | mbedTLS 3.6.5 (Apache-2.0 OR GPL-2.0+, smaller, weaker CMS support), Botan 3.12 (BSD-2), libsodium (ISC, no X.509/CMS) | Only OpenSSL covers CMS/PKCS#7, X.509, XMLDSig primitives, and every digest in one permissive package. | D-37 | External signer process | `--sign-command=CMD` is the one opt-in exception to the no-subprocess rule | No external signers | Real signing often requires platform tools (apksigner, signtool) and HSM-held keys | Decided 2026-10-08 |
| D-38 | Default write layout | `--layout=stable` by default: keep payload offsets and bytes, absorb growth into padding, write PDF incremental updates. `--layout=compact` re-serializes everything for users who want a clean rewrite | `compact` canonical rewrite | Minimizes byte churn, keeps external offsets valid, and stores efficiently in Git | Decided 2026-10-08 (amended) |
| D-39 | Integrity default | `--integrity=recompute`: fresh values on regenerated units. | D-40 | Bit-exact recompression | Deferred. Patches are content-level, and `--exact` carries encoded bytes when byte equality matters. Later candidates: preflate (C++, Apache-2.0 per a third-party listing, verify), preflate-rs (Rust, format incompatible with preflate, license unverified), and Chromium Puffin (deterministic deflate for patching, license to verify) | Implement now | Correctness does not need it. | D-41 | Encrypted content | v1 treats it as an opaque leaf, except look-through for PDF permission-only encryption (empty user password). | D-42 | Long-option collision rule | No GNU abbreviation of ≥ 4 characters may change meaning in any personality. `--report` was renamed to `--json` | Zero collisions at any length | A strict rule makes almost every new option name impossible, and four characters covers realistic typing | Decided 2026-10-08 |
| D-43 | Keys for keyed MACs | Only user-supplied keys (`--mac-key=FILE`, env, or Git config). Users who legitimately hold a key can supply it | Decided 2026-10-08 |
| D-44 | v1 format scope | Text, binary, containers (ZIP/TAR), XML, JSON, CSV, PNG, JPEG, other rasters (TIFF, GIF, WebP, BMP, TGA, QOI), SVG, PDF, SQLite, simple meshes (OBJ, PLY, STL) | A broader first release | These formats match the plan's Phases 2–6 plus SVG, PDF, SQLite, and meshes, and share the core primitives | Decided 2026-10-08 |
| D-45 | v1 scope inside each format | v1 = the format document's MVP row plus every later row that a decided item depends on. | D-46 | PDF in v1 | MVP plus the incremental writer plus annotation and form merge with carrier logic. Page-content merge (Q-PDF-4) follows after v1 | Page-content merge in v1 as well; metadata-only merge in v1 | `--layout=stable` is the default (D-38), so every PDF merge needs the incremental writer. | D-47 | Recursion contract | A `Context&` (registry, shared `Limits` budget, depth, format option values) in every Load/Diff/Merge/Save options struct (SPEC §4) | A global registry and per-call limits | Containers and SQLite recurse in v1. | D-48 | APNG files in the PNG module | APNG: diff and merge the default image only; frame chunks are an OpaqueLeaf taken whole from one side, and both-sides frame changes conflict `unsupported` | Treat APNG files as opaque binaries | Keeps `.apng` files mergeable for their still image without frame support | Decided 2026-10-08 |
| D-49 | `--scan-streams` | Post-v1 (the option, not only its default). The hint in the binary report is removed until then | Ship it in v1, off by default | It is in no binary.md phase and needs lz4; v1 users lose nothing they had | Decided 2026-10-08 |
| D-50 | Digests without crypto in v1 | JAR is handled as plain ZIP with `--signatures=auto` stripping; touched entries lose their `MANIFEST.MF` digest lines with a warning (unsigned JARs ignore them). JPEG IPTC/XMP digest fields stay OpaqueLeaf (no recompute). Overrides Q-ZIP-12 and Q-JPEG-9 until the crypto feature ships | Allow OpenSSL libcrypto for digests only in v1; refuse such merges as `unsupported` | §12.8 forbids own crypto primitives and the crypto feature is deferred (D-36). | D-51 | Format-specific options | Each `Format` declares its long options (`FormatInfo::options`); the parser merges them into each personality's table at registration; CI runs the D-42 collision test over the merged tables | One global option table maintained by hand | CLI.md lists only core options, yet formats document dozens (`--png-*`, `--pdf-*`, `--zip-*`). Declaring them next to the code keeps the collision test complete | Decided 2026-10-08 |
| D-52 | vcpkg baseline | Pin `builtin-baseline` in `vcpkg.json` to the vcpkg commit current at Phase 0 and record dependency versions in `docs/DEPENDENCIES.md`; bump deliberately | Float on the latest ports | Format docs cite versions newer than the local vcpkg tree (qpdf 12.4.2 vs 12.4.0, libpng 1.6.59 vs 1.6.58); a pin makes builds and golden files reproducible | Decided 2026-10-08 |
| D-53 | Version-control integrations | Git is the only built-in VCS adapter. Adapters are thin argument and exit-code mappings over the public library API (SPEC §10), so integrations for other systems can be built separately from the core | Built-in adapters for several VCSs | One adapter keeps the core small. The thin-adapter rule keeps the merge logic reusable by any host | Decided 2026-10-08 |
| D-54 | Inputs that detect as different formats | Diff and merge them as `text` with the warning `formats-mixed` when every input is text underneath (no NUL in the first 8 KiB); otherwise as `binary`. `--format`/`-a` override (SPEC §11) | Refuse with trouble unless `--format` is given (the earlier SPEC §11 rule); merge as bytes (the earlier code) | A text file that fails its structured parse (conflict markers in `.json`) still merges usefully, and the warning says why. Refusing breaks Git merges of half-resolved files | Decided 2026-10-10 (#41) |
